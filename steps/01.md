# Samilpo SMC 文件格式逆向研究：第一阶段

## 目标

通过 REA MCP 和 Ghidra，静态分析以下程序中负责读取、解析 `.smc` 乐谱文件的代码：

- `C:\Program Files (x86)\Samilpo 2.0\MusicBook.exe`
- `C:\Program Files (x86)\Samilpo 2.0\engine.dll`

示例文件：

- `C:\Program Files (x86)\Samilpo 2.0\8000Songs\500KFS\500KFS-0041.smc`

最终项目目标是建立 SMC 文件格式说明文档，尽可能恢复字段结构、偏移、长度、编码和语义，用于数字遗产保存。

**本次仅执行第一阶段：定位文件解析代码，恢复主要调用链，建立文件格式的初步结构。暂不要求解释全部字段，也不编写转换器。**

## 已知信息

1. 程序可能基于修改过的 MFC。参考 SDK 位于 `C:\MSVC600-master`。该 SDK 只能作为参考，不能直接假定二进制中的类型或函数布局与其一致。
2. SMC 歌词使用特定的韩文编码，具体编码尚未确认。
3. 软件可以展示五线谱、歌词、常规乐谱注解，播放 MIDI，并在播放时显示同步光标。部分曲目包含图片、多页乐谱。
4. 研究对象为旧式朝鲜乐谱软件。研究目标是文件格式的互操作性和数字保存。

## 工具与范围

- 使用已连接的 REA MCP 和 Ghidra。
- 遵循 REA skill 中适用于原生二进制静态分析的工作流。
- 不执行目标程序，不修改原始 EXE、DLL 或 SMC 文件。
- 优先研究文件打开、读取、解析、数据结构初始化等路径。
- 只在发现明确关联时进一步分析渲染、MIDI 播放和翻页功能。
- 不需要全面分析 UI、资源管理、与 SMC 格式无关的 MFC 框架代码。
- 不要直接将大量反编译代码输出到对话中。

## 第一阶段任务

1. 确认 EXE 和 DLL 的架构、导入关系及潜在分工。
2. 检索 `.smc` 扩展名、文件打开逻辑、CFile 相关调用和已知文件读取 API。
3. 找到负责读取 SMC 数据的候选函数，记录模块、地址、函数入口及调用关系。
4. 追踪文件头及主要数据块的解析路径，尝试恢复初步的字段结构。
5. 根据证据判断是否存在解压、解密、编码转换或其他预处理步骤。
6. 标记与乐谱元素、歌词、图片、分页、MIDI 事件可能相关的解析分支，暂不要求全部深入。
7. 总结当前证据和后续需要分析的函数，给出按收益排序的研究计划。

## 研究效率要求

- 尽量复用同一个 Ghidra 分析会话，避免重复打开和完整分析同一模块。
- 优先进行函数定位与局部反编译，不对整个程序逐函数生成报告。
- 对复杂函数，只分析与当前 SMC 数据路径相关的部分。
- 对已有结论先查阅 workspace 文件，避免重复探索。
- 区分直接证据、合理推断和未知事项，不要为了填满文档而猜测。
- 对无法确认的字段或函数，记录疑点和验证方法，暂时跳过。
- 不进行无明确目标的大规模循环搜索。

## 持久化成果

所有中间成果保存到当前 workspace，不要只保存在对话历史中。

至少建立：

- `research-state.md`：进度、已确认结论、下一步工作
- `function-index.md`：模块、函数地址、作用及证据
- `smc-format.md`：文件格式的初步结构，未知部分明确标注
- `open-questions.md`：未解决问题及建议验证方法

优先保存简洁的结构化结论和可回溯地址，而不是复制完整反编译输出。

## 本次停止条件

完成主要 SMC 解析入口的定位，并建立初步解析调用链和数据结构假设后，停止调查并汇报。

如果缺少 SMC 样本、缺少分析工具能力，或者遇到需要大量额外调查才能继续的障碍，应记录当前发现并停止，不要无限尝试。

**本次以建立可靠研究基础为目标，不追求一次性完成整个 SMC 格式文档。**
